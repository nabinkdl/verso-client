## 1. Snapshot

- NestJS 12 (ESM) + Prisma 7 + PostgreSQL (Neon), JWT auth via Passport, Resend for password-reset email, Swagger, Vitest.
- Built: auth, users/profiles/search/follows, posts/feed/likes/comments, health, Prisma error mapping, env validation, and chat (REST history + Socket.IO gateway at `/chat`).
- Designed but **not built**: refresh tokens, saved posts, reels endpoints, notifications, pages, marketplace, unified search, media uploads → [`docs/API-DESIGN.md`](../../docs/API-DESIGN.md).

## 2. Run & verify

From repo root:

```bash
npm run dev:api        # nest start --watch → http://localhost:3000/api
npm run build:api      # prisma generate && nest build
npm run start:api      # node dist/main.js (cwd apps/backend)
npm run test --workspace @mononet/backend              # vitest run (unit)
npm run test:e2e --workspace @mononet/backend          # supertest e2e
npm run lint           # oxlint --type-aware src/ test/
npm run typecheck      # tsc --noEmit
npm run format         # prettier on src, test, prisma
```

Database:

```bash
npm run db:migrate     # prisma migrate dev (creates a migration)
npm run db:deploy      # prisma migrate deploy (production)
npm run db:generate    # prisma generate
npm run db:seed        # DESTRUCTIVE: wipes and reseeds demo data
npm run db:studio      # Prisma Studio
```

Swagger: <http://localhost:3000/docs>, OpenAPI JSON at `/docs-json`. Meta route: `GET /api`. Health: `GET /api/health` (checks `SELECT 1`, `503` if DB down).

Nx alternatives (targets in `apps/backend/project.json`): `npx nx run @mononet/backend:dev`, `npx nx run @mononet/backend:build`, `npx nx affected -t typecheck test`. `build`, `lint`, `typecheck`, `test`, and `db:generate` are cached; the first four `dependsOn` `db:generate`, so the generated Prisma client is restored on a cache hit. Git hooks: pre-commit runs type-aware `oxlint` on staged backend files, pre-push runs `nx run-many -t typecheck test`.

## 4. Request lifecycle (`main.ts`)

1. `NestFactory.create<NestExpressApplication>(AppModule)`
2. `helmet` with a CSP that allows inline styles/scripts and `https:` images (`upgradeInsecureRequests` disabled for local HTTP)
3. CORS from `CORS_ORIGIN` (comma-separated or `*`)
4. Static assets from `<cwd>/public` **if it exists** (single-port image only; dev usually has none)
5. `app.setGlobalPrefix(API_PREFIX)` → everything is under `/api`
6. Global `ValidationPipe({ transform, whitelist, forbidNonWhitelisted, enableImplicitConversion })`
7. Global `PrismaExceptionFilter`
8. Swagger at `/docs` (outside the API prefix)
9. `listen(PORT)`, shutdown hooks enabled

Auth is **not** global: each route opts in with `@UseGuards(JwtAuthGuard)` or `@UseGuards(OptionalJwtAuthGuard)`.

The Socket.IO server is installed with `SocketIoAdapter(app, corsOrigin)`, which mirrors `CORS_ORIGIN` (the default adapter ignores `enableCors`). The gateway lives on the `/chat` namespace; the global `/api` prefix does **not** apply to WebSockets.

## 5. Auth model

- JWT bearer, HS256, secret `JWT_SECRET` (min 32 chars), expiry `JWT_EXPIRES_IN` (default `7d`).
- Payload: `{ sub, email, username }`; `JwtStrategy.validate` re-reads the user from the DB on every request and returns `{ id, email, username }`, so deleted accounts get `401`.
- `@CurrentUser()` extracts that object (`AuthenticatedUser` for protected routes, `null` for optional ones).
- `OptionalJwtAuthGuard` intentionally swallows invalid/expired tokens and returns `null`; public reads then omit viewer state.
- **No roles/abilities layer.** Authorization = ownership/membership checks inside services (`assertPostOwner`, `author`, `post.authorId`), returning `403` via `ForbiddenException`.
- Register/login return `{ accessToken, user }`. No refresh token, no logout endpoint, no token revocation: a password change or reset does **not** invalidate existing tokens.
- Passwords: bcryptjs, cost 12, 8–72 chars. Usernames are lowercased and trimmed before storage/lookup.
- WebSocket auth: the client sends `{ auth: { token } }`; `ChatGateway.handleConnection` verifies the JWT, attaches `{ id, username }` to `socket.data`, joins `user:<id>`, then checks the account still exists. Invalid tokens get `chat:error` and a disconnect. Handler-level authorization relies on that identity plus the joined conversation room; membership is checked on `conversation:join` and on every REST call.
- Password reset: 32-byte random token, SHA-256 hashed at rest, single-use, TTL `PASSWORD_RESET_TOKEN_TTL_MINUTES` (60), previous unused tokens deleted, token row removed if the email send fails.

## 6. Data layer

- Prisma 7 with the `@prisma/adapter-pg` driver adapter (`PrismaPg`), created in `PrismaService` from `DATABASE_URL`; `$connect`/`$disconnect` on module lifecycle.
- `schema.prisma` has **no `url`** in the datasource block. The CLI gets its URL from `prisma.config.ts` (`env('DATABASE_URL')`).
- Generated client goes to `src/generated/prisma` (`prisma-client` provider) and is **gitignored**. Import from `.../generated/prisma/client.js`; Prisma enums (`MediaType`) come from the same module.
- Models: `User`, `PasswordResetToken`, `Follow`, `Post`, `Like`, `Comment`, `Conversation`, `ConversationParticipant`, `Message`. Cascades: user → posts/comments/likes/follows/tokens; post → likes/comments. `Like` and `Follow` use composite primary keys (natural idempotency).
- Indexes mirror query shapes: `posts(authorId, createdAt desc)`, `posts(createdAt desc)`, `comments(postId, createdAt)`, `follows(followingId)`.
- `seed.ts` deletes all rows in FK order, then inserts 6 demo users (`Password123!`, `alex@mononet.dev` / `alexm`), posts with picsum images, follows, likes, comments. **Never point it at production.**
- Media is URL strings only; the API never stores files and does not verify URLs are reachable.

## 7. API conventions

- Global prefix `/api`; resources are plural nouns; user routes address by lowercase **username**, everything else by `cuid` id.
- Lists: `cursor` = id of the last row + `limit` 1–50 default 20; envelope `{ data, meta: { nextCursor, hasMore, limit } }`. Ordering must include `id` as a tiebreaker for stable keyset pagination.
- Bounded/legacy lists return plain arrays: user search (≤50) and post comments (≤200, not paginated).
- Mutations return small envelopes: `{ liked, likeCount }`, `{ following }`, `{ deleted: true }`, `{ message }`.
- Like/follow/save semantics are idempotent (`upsert` / `deleteMany`).
- DTOs live beside their feature and carry both `class-validator` and `@ApiProperty` metadata. Unknown body fields are rejected (`forbidNonWhitelisted`), so every accepted field must be declared — including optional ones.
- Strings that are identifiers (username, email) are normalized with `@Transform` (trim/lowercase) in the DTO, and re-normalized in the service before lookup.
- Fields are camelCase in JSON; enum values are UPPER_SNAKE (`IMAGE`, `VIDEO`) because Prisma enums are serialized directly.
- Response objects are Prisma selections. **Changing a `select`/`include` is an API contract change.**
- Errors: Nest default `{ statusCode, message, error }`; validation puts an array in `message`. `PrismaExceptionFilter` maps `P2002 → 409`, `P2003 → 409`, `P2025 → 404`; other known Prisma errors log and return a generic `500`.
- Viewer-enriched reads (`likedByMe`, `isFollowing`, `isMe`) combine `OptionalJwtAuthGuard` with a conditional select/where clause — never leak private data to make this work.
- `PRIVATE_USER_SELECT` (includes `email`) is only for `me`/auth responses; `PUBLIC_USER_SELECT` is for everyone else. `PRIVATE_USER_SELECT` in a profile route is a privacy bug.

## 8. Environment

`validateEnv` runs at startup and throws on bad config (so `AppModule` cannot load without it).

| Var | Required | Default / rule |
| --- | --- | --- |
| `NODE_ENV` | no | `development`; one of development/test/production |
| `PORT` | no | `3000`, integer 1–65535 |
| `API_PREFIX` | no | `api` |
| `CORS_ORIGIN` | no | `http://localhost:5173`; comma-separated or `*` |
| `DATABASE_URL` | **yes** | pooled Postgres URL used by the app |
| `DATABASE_URL_UNPOOLED` | documented | direct URL for migrations — **not read by any code today** |
| `JWT_SECRET` | **yes** | min 32 chars |
| `JWT_EXPIRES_IN` | no | `7d` |
| `RESEND_API_KEY` | no | empty ⇒ email disabled (logged warning) |
| `RESEND_FROM_EMAIL` | no | `Verso <onboarding@resend.dev>` |
| `APP_URL` | no | `http://localhost:5173`, used to build the reset link |
| `PASSWORD_RESET_TOKEN_TTL_MINUTES` | no | `60`, positive integer |

Env file lookup: `.env` then `backend/.env` relative to the process cwd (workspace scripts run with cwd `apps/backend`). `.env` is gitignored; `apps/backend/.env.example` is the template.

## 9. Testing

- Unit: Vitest, globals enabled, colocated `*.spec.ts` (`**/*.spec.ts` only), `resolve.tsconfigPaths`.
- E2E: separate `vitest.config.e2e.ts` + `test/app.e2e-spec.ts` using supertest. It imports the real `AppModule`, so it needs a valid `.env` **and a reachable database**; the file only exercises `GET /api`.
- The e2e bootstrap sets the prefix manually and does **not** install the global ValidationPipe, Prisma filter, helmet, or Swagger — e2e behavior differs from production until the test mirrors `main.ts`.
- Services are tested by instantiating them with a mocked `PrismaService`; there is no test-database fixture or transaction rollback.

## 10. Gotchas / traps

1. **ESM + NodeNext:** every relative import must end in `.js` (`./auth.module.js`), even for `.ts` files. Missing extensions fail at runtime/build, not in the editor.
2. **PRISMA_CLIENT_IS_GENERATED:** after cloning or changing `schema.prisma`, run `npm run db:generate`. `npm run build:api` does it automatically; a watch server started before generation keeps the old client — restart it.
3. **Never edit `src/generated/prisma`** and never import `@prisma/client` directly; use the generated path.
4. **CLI vs runtime URLs:** `prisma.config.ts` uses `DATABASE_URL` for migrations/seed. `DATABASE_URL_UNPOOLED` is documented for Neon migrations but unused — point `DATABASE_URL` at the direct host for a migration run, or wire the unpooled var into the config.
5. **Strict DTO whitelist:** an extra property in the body is a `400`, and a missing `@ApiProperty` field does not show in Swagger even though validation accepts it.
6. **`enableImplicitConversion` is on globally**, so query strings become numbers/booleans when possible; still use `@Type(() => Number)` for numeric query params with defaults (see `PaginationQueryDto`).
7. **Guard-less routes are public.** Swagger's lock icon comes only from `@ApiBearerAuth()`, which does not enforce anything — the guard does.
8. **`OptionalJwtAuthGuard` hides auth errors**, including expired tokens. A client with a stale token silently gets anonymous data on those routes.
9. **No token revocation:** logout is client-side only; a reset password leaves old JWTs valid for up to 7 days. If that matters, implement `tokenVersion`/refresh tokens (see API design §1.3).
10. **Post comments are capped at 200 and unpaginated.** Changing to the paginated envelope is a breaking UI change (API design §1.1).
11. **`buildPaginatedResult` requires an `id` field** and assumes the query fetched `limit + 1`; it does not know about custom ordering.
12. **Email without a key:** `forgot-password` returns the generic 200 for unknown emails, but for a real account with no `RESEND_API_KEY` (or a rejected send) it returns `503` and deletes the token row.
13. **Resend sandbox sender:** `onboarding@resend.dev` can only deliver to the Resend account owner until a domain is verified.
14. **Static `public/` shadowing:** if `apps/backend/public` exists (single-port artifact), `main.ts` serves it; stale files there can confuse manual API testing at `/`.
15. **Prisma `P2025` means "record not found"**, which is why delete flows must check existence first if they want a specific message.
16. **Validation errors from Prisma** (e.g. a bad field passed programmatically) are `PrismaClientValidationError`, not *known request* errors — the filter will **not** catch them and they surface as `500`.
17. **`bcryptjs`, not native `bcrypt`** — pure JS, cost 12; keep the cost in one place (`PASSWORD_ROUNDS`).
18. **Migrations are committed**; do not use `db push` in this repo, and do not edit applied migration files.
19. Docker builds run `prisma generate` and `nest build` with a dummy `DATABASE_URL`; runtime config comes from `apps/backend/.env` via compose `env_file`.
20. The UI is served from the same origin only in single-port/Docker mode; in dev, CORS must include `http://localhost:5173`.
21. **Socket events can arrive before async auth finishes.** Socket.IO emits `connect` on the client as soon as the transport is up, while `handleConnection` may still be awaiting. Verify the JWT synchronously and set `client.data.user` **before** any `await`, or the first `conversation:join` is rejected as unauthorized. The DB existence check can run after.
22. **WS CORS is separate from HTTP CORS.** Installing `@nestjs/platform-socket.io` is not enough; without `SocketIoAdapter`, the handshake from `:5173` is rejected even though REST works.
23. **Raw SQL must quote Prisma's camelCase columns.** `@@map` renames tables only; columns stay `"conversationId"`, `"lastReadAt"`, `"senderId"`. `p.conversation_id` fails with Postgres `42703`.
24. **Neon latency is seconds, not milliseconds** in this environment. Chat handlers were written to minimize round trips (join = one query; message create returns participant ids for broadcast). The UI uses a 15s socket ack; do not resend on ack timeout — the message may already be persisted.
25. **Socket.IO rooms are in-process.** A second API instance will not deliver messages to clients connected elsewhere; add `@socket.io/redis-adapter` before scaling horizontally.
26. **Message edit/delete and group chat are modelled but not exposed.** `Message.editedAt/deletedAt` and `ConversationType.GROUP` exist with no endpoints yet.
27. **Socket JWTs are not revocable.** The gateway checks that the user row still exists, but a stolen token works until it expires (7d default), same as REST.

## 11. Adding a feature module — checklist

1. Create `src/<domain>/` with `controllers/`, `services/`, `models/dto/`, `models/<domain>.model.ts`.
2. Define DTOs with `class-validator` **and** `@ApiProperty`; declare every accepted field.
3. Service takes `PrismaService`; put ownership/permission checks there; throw Nest HTTP exceptions with specific messages.
4. Controller: `@ApiTags`, `@ApiOperation` on every route, `@UseGuards(JwtAuthGuard)` + `@ApiBearerAuth()` unless public. Use `@CurrentUser()` instead of reading the request.
5. Register the module in `app.module.ts`.
6. Add a Prisma model + migration if needed (`npm run db:migrate -- --name <name>`), then `npm run db:generate`.
7. Add unit specs for authorization and edge cases; add an e2e path if the route is critical.
8. For realtime: add handlers to an existing gateway rather than a second Socket.IO server; authenticate in `handleConnection`, join rooms per resource, and emit to per-user rooms for list/badge updates.
9. Update [`README.md`](README.md) endpoint tables, [`docs/API-DESIGN.md`](../../docs/API-DESIGN.md) if the contract changed, and §3/§10 of this file.
